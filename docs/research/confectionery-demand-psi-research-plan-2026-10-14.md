# 菓子の季節・販促を加味した需要予測とPSIの研究計画

## 最新補足：平均・中央値・生産判断（2026-10-14）

現在の公開Store Sales数量研究では、mean/median/decision quantileを分ける方針を採る。集約見込のmean、典型値Q50、意思決定量を別field/評価にし、原データだけから実メーカーの費用・在庫・納期を補わない。独自の暦/水準入力の研究は進んでいるがメーカーPSIの採択は未完了。以下は当初の計画と履歴で、最新進捗はcurrent-handoffと研究roadmapを優先する。

策定日: 2026-10-14

状態: 研究設計。現在利用できるのはモック用データのみ。

## 1. 研究で答えること

菓子の季節・販促予定を入力し、出荷・販売量を予測して、生産・在庫判断を改善できるかを研究する。統計分析で説明できる部分を先に把握し、時系列モデルが追加する価値を確かめる。モックの画面、予測期間、粒度、実装言語への互換性は研究条件にしない。

主問は、**予測発行時点で知っていた季節・販促情報を使うことで、必要な先読み期間の誤差と偏りを減らせるか。その改善が欠品・在庫・廃棄の判断へつながるか**である。現在のモックで得られる精度は、菓子メーカーの実用精度の根拠にはしない。

TimesFM 3は過去の説明系列と将来既知の説明系列を区別し、販促予定を入力する例を公開している。この構造は本用途の候補となる。ただし、公式例から対象企業の精度や販促の因果効果は判断できない。[Google Research](https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/)

Bantoの小型独自モデルは過去3連続系列を入力する構造で、将来販促・暦・価格を受け取る経路がない。需要用途へ進めるなら入力契約から設計する。工業信号の[一回探索](timesfm3-small-model-pilot-2026-10-14.md)の成績は需要予測へ移さない。

## 2. 予測対象と支援する判断

最初に支援する判断を一つ選び、実際の製造・調達リードタイム、計画を変更できない期間、賞味期限を確認する。原本は可能なら日次の品目×得意先または販売チャネルで保持する。日次・週次・月次への集約は判断に合わせる。

| 支援する判断 | 予測に必要な量 | 粒度・期間を決める条件 |
| --- | --- | --- |
| 補充・生産着手 | 補充が届くまでの累積出荷・販売量 | 製造/調達リードタイム＋見直し間隔。賞味期限が短い場合は日次を優先 |
| 販促前の能力・資材確保 | イベント前後の出荷量とピーク | 生産能力・資材調達が変更できる時点まで |
| 中期の能力計画 | 品目群・月等の集約量 | 計画変更の周期と長期イベント予定の確度 |

画面で表示する期間と、精度を重視する先読み期間は分ける。長期予定が未定の場合、通常・販促実施・中止等の条件付きシナリオを示す。

出荷、受注、消費者の販売数量、潜在需要は異なる目的値である。メーカー出荷を予測する場合、小売で売れる時期より前の積み増しと販促後の反動も検討する。受注・出荷・POSを同じ数量として加算しない。食品企業でsell-inとsell-outを分けて予測・連携する研究例があるが、その報告精度を本用途へ移さない。[Amazon Science](https://www.amazon.science/publications/enhancing-sell-in-and-sell-out-forecasting-using-ensemble-machine-learning-method)

供給制約や欠品がある期間は、観測出荷・販売量が潜在需要を下回り得る。潜在需要を推定する場合、推定値を実測の正解に置き換えず別の研究課題とする。[FreshRetailNet論文](https://arxiv.org/abs/2505.16319)

## 3. 必要な入力と時点

各レコードに実施・対象日と、予測で利用可能になった日時を持たせる。訂正・計画変更は版を残し、起点ごとに当時利用できた版を選ぶ。未記録の販促予定は「販促なし」と区別する。

| 入力 | 必要な項目 | 予測時の扱い |
| --- | --- | --- |
| 実績 | 品目、得意先/チャネル、日付、数量、単位、返品・取消、確定状態、改訂 | 知識締め時点までの確定情報。欠測と実績0を分ける |
| 暦・季節 | 営業日、曜日、休日、季節行事の日付、行事まで/後の日数 | 将来既知。前年の同じ週番号だけに依存しない |
| 販促・価格 | 対象、開始/終了、予定/承認/実施済み、値引き、媒体・売場等、取消、利用可能日時 | 起点で既知の予定版。実施後の結果ラベルを先読みしない |
| 供給・在庫 | 欠品、出荷制限、在庫、未充足注文、供給停止 | 需要の抑制と供給制約を区別。将来実績を説明変数にしない |
| 品目情報 | 単位換算、有効期間、新商品/終売、カテゴリ、賞味期限 | 履歴の対応と代替品の扱いを固定 |
| 生産・調達 | リードタイム、能力、ロット、計画固定期間、納期 | PSIの条件。予定と完了入庫を区別 |

節分・バレンタイン・ホワイトデー・連休・お盆・年末等は候補であり、対象品目に関係する行事だけを選ぶ。行事前後の出荷移動、販促の前倒し購入・反動、代替品への移動を仮説として整理する。売上金額を目的値にする場合は価格の影響が数量と混ざるため、数量予測と分ける。

天候を使うなら、将来の観測値と予報を区別する。未知の説明変数を仮定した予測区間は、その仮定に条件付けられている。予定変更自体の不確実性は別途扱う。[FPP3 動的回帰](https://otexts.com/fpp3/dynamic-regression.html)

## 4. 統計分析とモデルを組み合わせる順序

### 季節・イベントの統計モデルを先に置く

通常の周期、傾向、イベント前後のずれ、品目間の共通性を可視化する。欠測・欠品・新商品・終売を確認してから、季節項とイベント項を持つ回帰を一つ作る。年周期は少数のFourier項、曜日/営業日は暦項、イベントは前後期間の項で表す。残差の自己相関が残る場合にARIMA誤差を組み合わせる。[FPP3 動的回帰](https://otexts.com/fpp3/dynamic-regression.html)

例えば、数量に適した変換を選んだ上で、

`変換した数量 = 通常水準＋季節/暦＋イベント前後/価格＋時間的な誤差`

と分解する。関係が非線形で単純回帰に不足する証拠があればGAM等を検討する。少数品目や年に一度の行事では複雑な品目別係数を増やさず、品目群で情報を共有する方法を検討する。季節分解・尺度・特徴量生成も評価起点の過去だけで推定する。

この寄与分解は予測モデルの説明である。季節に合わせて販促を実施する等の交絡があるため、係数・重要度・attentionを「販促をしなかった場合との差」と解釈しない。販促施策の因果効果や最適な施策選択は、比較可能な対照・実験等を設計する別課題とする。

### 初回の候補を絞る

基準は季節naive、研究候補は上記の統計モデル一つ。必要なら同じ利用可能情報を使うGBM一つを加える。モデルの種類を増やす前に、「予定情報なし→あり」の差を確認する。供給制約を含む評価と、制約のない期間の評価を分ける。

| 併用方法 | 追加する理由 | 条件 |
| --- | --- | --- |
| 統計モデルと機械学習の予測を平均 | 誤差が互いに補い合う | 過去検証で確認後、一方式だけ追加。最初は固定の単純平均 |
| 統計予測＋機械学習による残差補正 | 統計で説明した後にも予測可能な構造が残る | 過去起点の外部予測から残差を作る。当てはめ残差だけで学習・評価しない |
| 統計で選んだ季節・イベント特徴を多要素モデルへ入力 | 予定と関連系列から条件付き予測を学ぶ | target/過去のみ/将来既知/missingの役割とmaskを実装 |

予測平均は有力な方法だが、本用途で改善するかは検証する。分位点の平均を、予測平均の分布の分位点と同一視しない。[FPP3 予測の組合せ](https://otexts.com/fpp3/practical.html)

独自モデルへ進む条件は、利用可能な予定情報と関連系列があり、既存候補に具体的な不足が見つかること。カテゴリ属性、可変系列数、欠測、季節を表せる履歴長、将来既知入力を需要用途として設計する。TimesFM 3の重みを利用する研究と、独立初期化した自作モデルを学習する研究は成果を区別し、既存のライセンス・配布境界を維持する。

## 5. 少数ケースと実用性評価

まず新しい匿名の例で、入力と判断の対応を確認する。既存モックの成績を上げるための再学習はしない。

| 代表ケース | 確認する動作 |
| --- | --- |
| 通常の季節・営業日変動 | 未来の暦を入力でき、事後実績を参照しない |
| 季節のピークから時期をずらした販促 | 過去年周期と将来予定を区別できる。反応の大きさは仮定/学習結果として明示 |
| 販促中止・変更・未定 | 起点で知っていた版だけが予測へ入る。未定をゼロにしない |
| 欠品・出荷制限 | 低い実績を需要減と断定せず、欠測や0とも区別する |
| 先行出荷・販促後の反動 | イベント当日の販売とメーカー出荷の時期を区別する |
| 確定注文と予測の重複 | 需要の範囲を照合し、同じ注文を二度計上しない |

架空例は入力経路と機構の確認用。生成式に合うことを実需要での優劣にはしない。

実用精度は、当時の利用可能情報を守った複数起点の予測で確認する。モデル・係数・組合せの選択は過去側で終え、将来実績は最終評価に使う。必要な先読み期間を直接評価する。[FPP3 時系列交差検証](https://otexts.com/fpp3/toolbox.html)

評価は品目×起点×leadの対応を保持し、通常/イベント/供給制約、先読み期間別にMAE・WAPE・Biasを示す。分母0や対象なしは理由付きnullとし、除外数も残す。分位点を出すならpinball・区間幅・実測coverageを確認する。重なる起点・同じイベント年の予測を独立した季節の繰返しと数えない。実データの合格水準は、数量単位と業務上の過不足コストを確認してから定める。

## 6. PSIへの接続

予測誤差と生産・在庫判断の評価を分ける。予測だけを替える比較では、需要実現値・初期在庫・入庫・リードタイム・能力・ロット・賞味期限・補充方針を共通にする。指標は欠品/未充足、在庫、廃棄・期限切れ、変更負担等から判断に関係するものを選ぶ。

確定注文が予測の内数なら、その範囲を消し込む。注文を予測へ単純加算せず、外数の特別注文は根拠付きで別処理する。予定生産を完了入庫へ置き換えず、単位換算と有効期限を保持する。

最初は確率を付けない通常・販促実施・中止・供給遅れ等の一貫したシナリオで、判断の感応度を確かめる。実データと確率モデルが整ってから、リードタイム全体の累積需要の分布を扱う。各日のp90の和は累積需要のp90とは限らず、週を跨ぐ変動や品目間の依存も必要になる。[FPP3 集約の予測区間](https://otexts.com/fpp3/practical.html)

モデルの80%予測区間から、そのままPSIの欠品確率や最適安全在庫を決めない。能力・納期・期限と意思決定方針を含む検証が必要である。

## 7. 次の研究unitと停止条件

**次は、年間季節性と販促予定の追加価値を検証できる公開食品小売データの適格性を、原本の大量取得や学習の前に確認する。** 確認項目は、複数年の履歴、食品との対応、販促/価格/暦の項目、将来可用性の根拠、欠品、数量単位、利用条件、取得方法と容量。採用できる候補を一つに絞り、少数の系列・固定期間・統計モデル一つで始める。公開小売の結果は菓子メーカー出荷の実証とは分ける。

欠品を扱う候補のFreshRetailNet-50Kは、公式カードに販促割引・在庫状態・90日系列・正規化数量を記載する。短期の販促/欠品研究には候補となるが、年間季節性やメーカーの生産ロット数量をそのまま検証できない。予定版の可用性も別途確認する。現時点で採用・取得・学習は行っていない。[公式データカード](https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K)

年間季節性を扱える候補と、短期の販促・欠品を扱える候補が一つで満たせない場合、研究の問いを分ける。実施結果だけがあるデータは、未来既知予定の実用評価と称さない。データの利用条件や可用性を確認できなければ、その地点を保存して止める。追加モデル比較で不足を埋めない。

メーカーでの実用性検証は、実出荷/受注/POSの意味と単位、販促予定履歴、供給制約、判断に必要なリードタイムが整ってから開始する。現時点はモック用データのみで、メーカー精度・販促因果効果・PSI方式の採択は未確定。

## 保存と研究境界

Astraの独立read-only検討を反映。別セッションのモックは参考として読取り、固有数量・顧客情報・原資料を本計画へ転記しない。今回の成果は用途・入力・評価計画で、モデル実行や実績データの取得は行っていない。公開カードの表示例は閲覧したが、データ本体の取得・評価には進んでいない。

実行側の上限、EvidenceStoreの分割と失敗予備、閉鎖root不変を維持。既存の正式gate・登録holdout・native経路は変更しない。自動実行の再開はこの計画作成とは別に扱い、既存automationのPAUSEDを維持する。
