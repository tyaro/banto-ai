# R0.2: 全モデル更新比較の基準とR1の扱い

2026-10-17 JST。人がFableの推奨を承認して定めた、R0.1数値契約への追加規則。機械可読版は[R0.2](../../examples/configs/rust-small-forecaster-r0.2-amendment-20261017.json)。[R0.1](../../examples/configs/rust-small-forecaster-r0-20261016-r0.1.json)のファイル・許容差の値・参照・R1の合格条件は変更しない。

## 背景

[R2P工程4](rust-r2p-full-model-contract-2026-10-17.md)の固定時に、全モデルのAdamW更新後のparameterをR0.1の1更新許容差で比べることは数値的に成り立たないと分かった。AdamWはsqrt(v)+epsで割るため、|勾配|がeps程度以下の要素では、丸め誤差の違いが更新量の違いとして増幅される。同じ問題は計画上の正式R2（CARE fold0の1更新・8更新・成熟state import）にも当てはまる。またR1は、最終出力は全件条件内だが累積中間値1点が未達のまま、正式R2の入口を止めていた。

## 決定1：更新の比較方法（正式R2以降）

| 判定 | 内容 |
| --- | --- |
| loss | 毎更新。1回目はnormalized_loss、2回目以降はeight_step_loss |
| 勾配 | 毎更新、全trainable tensor。R0.1のgradient規則（要素ごと＋全体の相対L2または参照0の規則） |
| parameter・1次/2次moment | その更新の種類のR0.1許容差。ただし「比較する更新までの全更新で参照の|勾配|がK·eps以上」の要素だけを判定する。K=10 |
| 同一backendの再開 | bytes一致（R0.1のまま） |

- 除外した要素の数・tensor名・位置を毎回記録する。更新後のforward（正規化分位点）は記録するが判定には使わない（勾配が0やtieの要素が直接効くため）。
- 実データでどこかの比較更新の除外が10%を超えたら、採否の前に原因を調べる。
- K=10の根拠：1回目の更新でのparameterの勾配に対する感度はlr·eps/(|g|+eps)²で、|g|がeps程度だと約lr/eps、|g|≥10·epsなら十分小さい。結果に合わせた許容差の拡大ではない。

根拠（[確認ツール](../../tools/r2_comparison_criterion_probe.py)、工程4の人工fixture、float32対float64のTorch）：

| 項目 | 結果 |
| --- | --- |
| 8更新のlossの差 / 勾配の差（最大） | 1.1e−7 / 5.0e−8（いずれも許容差より十分小さい） |
| 1更新：R0.1のまま / K=10 | 18要素超過（最大1.10e−5） / 超過0、除外0.38% |
| 8更新：R0.1のまま / K=10 | 1要素超過 / 超過0、除外4.3% |
| 64更新後のstateを共有して1更新 | 除外なしでも超過0（最大7.2e−7、atol 1e−6に近い）、K=10でも超過0 |

## 決定2：R1の残1点と正式R2の入口

- R1の状態は変えない。累積中間値1点（train-last/blocks.1/index3450）は未達のままで、R1を合格とは扱わない。修正の調査も再開しない。
- 正式R2に入る条件を「R1の最終出力（正規化・元単位の分位点、固定7case全件）がR0.1内」かつ「同一入力の局所比較385件がすべてR0.1内」とする。
- 累積中間値の比較は毎回実行・記録する診断として残すが、正式R2を止める条件からは外す。
- 理由：差2.74e−6（限界2.57e−6、値0.028）は上流の累積によるもので同一入力の局所差は0。学習側の許容差（勾配atol 2e−5、8更新parameter atol 3e−6）と同じ桁で、一般的な修正の根拠もない。止める条件のままでは主目的の検証が無期限に止まる。
- 変えないもの：要素の除外、許容差の拡大、参照の再生成はしない。製品同等性は別に判定する。

## 次の順序

1. 正式R2を1回だけ行う（CARE fold0の1更新・8更新・成熟step4096 import）。学習済みstateはMacにあるため、Macで実行するか、stateをCloudへ移す方法を決めてから行う。
2. それを待たずに、保全の実用性評価の契約（必要な先行時間、許容する誤警報、event集計）を固定し、既存adapterでTimesFM・Chronos・Totoとの比較を行う。
3. R3とbanto接続は1・2の後。
