# R0.2: 全モデル更新比較の基準とR1の扱い

2026-10-17 JST。人がFableの推奨を承認して定めた、R0.1数値契約への追加規則。機械可読版は[R0.2](../../examples/configs/rust-small-forecaster-r0.2-amendment-20261017.json)。[R0.1](../../examples/configs/rust-small-forecaster-r0-20261016-r0.1.json)のファイル・許容差の値・参照・R1の合格条件は変更しない。

## 背景

[R2P工程4](rust-r2p-full-model-contract-2026-10-17.md)の固定時に、全モデルのAdamW更新後のparameterをR0.1の1更新許容差で比べることは数値的に成り立たないと分かった。AdamWはsqrt(v)+epsで割るため、|勾配|がeps程度以下の要素では、丸め誤差の違いが更新量の違いとして増幅される。同じ問題は計画上の正式R2（CARE fold0の1更新・8更新・成熟state import）にも当てはまる。またR1は、最終出力は全件条件内だが累積中間値1点が未達のまま、正式R2の入口を止めていた。

## 決定1：更新の比較方法（正式R2以降）

| 判定 | 内容 |
| --- | --- |
| loss | 毎更新。1回目はnormalized_loss、2回目以降はeight_step_loss |
| 勾配 | 毎更新、全trainable tensor。clip前とclip後の勾配、global norm、clip係数をR0.1のgradient規則（要素ごと＋全tensorまとめた相対L2、参照0なら候補L2）で比べる |
| parameter | 1回目はone_step_parameter、2回目以降はeight_step_parameter。ただし判定するのは「比較する更新までの全更新で、参照（Torch）のclip後勾配の大きさがK·eps以上」の要素だけ。K=10、eps=1e−8（recipeのAdamW eps）なのでK·eps=1e−7 |
| 1次・2次moment | first_moment・second_momentを全要素で比べる（除外しない） |
| 同一backendの再開 | bytes一致（R0.1のまま） |

- 「全更新」は、比較する実行の中で行った更新を指す。k回目の更新後を比べるときは1〜k回目のすべてで条件を満たす要素だけを判定する。成熟state（step4096）をimportして1更新する場合は、import後のその1更新の勾配だけで判定する（import前の4096更新はRust側で行わないため）。
- clip後の勾配を使うのは、AdamWに渡るのがclip後の勾配だから。
- momentを除外しないのは、mとvが勾配だけで決まり、epsによる割り算の増幅を受けないため。下の実測でも全要素で許容差内だった。
- 除外したparameter要素の数（全trainable要素109,024に対する割合）・tensor名・位置を毎回記録する。
- 更新後のforward（正規化分位点）は記録するが要素ごとの判定には使わない（勾配0やtieの要素が直接効くため）。forwardは次の更新のlossとしてだけ判定される。最後の更新の後は、その更新に使ったbatchのforwardを記録する。
- 実データでどこかの比較更新の除外が10%を超えたら、採否の前に原因を調べる。
- K=10の根拠：1回目の更新でのparameterの勾配に対する感度はlr·eps/(|g|+eps)²で、|g|がeps程度だと約lr/eps、|g|≥10·epsなら十分小さい。結果に合わせた許容差の拡大ではない。

根拠（[確認ツール](../../tools/r2_comparison_criterion_probe.py)、工程4の人工fixture、float32対float64のTorch）：

| 項目 | 結果 |
| --- | --- |
| 8更新のlossの差 / clip後勾配の差（最大） | 1.1e−7 / 5.0e−8（いずれも許容差より十分小さい） |
| 1更新のparameter：R0.1のまま / K=10 | 18要素超過（最大1.10e−5） / 超過0、除外0.38% |
| 8更新のparameter：R0.1のまま / K=10 | 1要素超過 / 超過0、除外4.3% |
| 64更新後のstateを共有して1更新のparameter | 除外なしでも超過0（最大7.2e−7、atol 1e−6に近い）、K=10でも超過0 |
| 1次・2次moment（1更新・8更新・成熟state、除外なし） | すべて超過0（最大差 1次8.7e−9、2次1.6e−12） |

人工fixtureではclip係数が1のため、clip前とclip後の勾配は同じである。実データで係数が1未満になっても、判定にはclip後の勾配を使う。

## 決定2：R1の残1点と正式R2の入口

- R1の状態は変えない。累積中間値1点（train-last/blocks.1/index3450）は未達のままで、R1を合格とは扱わない。修正の調査も再開しない。
- 正式R2に入る数値の条件を「R1の最終出力（正規化・元単位の分位点、固定7case全件）がR0.1内」かつ「同一入力の局所比較385件がすべてR0.1内」とする。
- R0.1のR1範囲にある数値以外の条件（分離build、backend・lockと依存ライセンスの一覧、CPU compile、非有限・mask・分位点順序の人工ケース）は引き続き入口条件に含める。正式R2の実行前に、それぞれの充足を確認して記録する。
- 累積中間値の比較は毎回実行・記録する診断として残すが、正式R2を止める条件からは外す。
- 理由：差2.74e−6（限界2.57e−6、値0.028）は上流の累積によるもので同一入力の局所差は0。学習側の許容差（勾配atol 2e−5、8更新parameter atol 3e−6）と同じ桁で、一般的な修正の根拠もない。止める条件のままでは主目的の検証が無期限に止まる。
- 変えないもの：要素の除外、許容差の拡大、参照の再生成はしない。製品同等性は別に判定する。

## 実データ学習の停止について

これまで「正式R2の実データ学習は停止中」としていた。R0.2により、上の入口条件を満たしたときに限り、計画上の正式R2（CARE fold0のtrain-prefixで1更新・8更新・成熟step4096 import）を1回だけ行ってよい。それ以外の実データ学習（追加のseed・学習延長・再校正・別fold）は引き続き停止で、R0.1の`current_execution`の記述も変えない。

## 次の順序

1. 正式R2を1回だけ行う。学習済みstateはMacにあるため、Macで実行するか、stateをCloudへ移す方法を決めてから行う。
2. それを待たずに、保全の実用性評価の契約（必要な先行時間、許容する誤警報、event集計）を固定し、既存adapterでTimesFM・Chronos・Totoとの比較を行う。
3. R3とbanto接続は1・2の後。
