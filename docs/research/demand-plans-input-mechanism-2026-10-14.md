# 販促予定の入力機構と需要研究の再開条件

2026-10-14。入力の時点選択・mask・取消の最小部品を確認済み。実績評価の自走は必要データ不足で停止。

## 今回までに分かったこと

[2016年検証](../results/store-sales-small-validation-2026-10-14.md)と[固定2017年評価](../results/store-sales-small-final-2026-10-14.md)を完了した。曜日・長期傾向・年周期の暦ridgeは2016年の全体MAEを減らしたが、2017年は週周期naiveより悪化し、8月に過大予測が続いた。今回の静的な暦回帰をそのまま採用する根拠はない。

次に確認したい販促予定の追加価値は、過去の予定版と利用可能日時を持つデータが必要。Store Salesのonpromotion実施値だけで、当時知っていた未来予定を復元できない。予測種類・seedを増やしてこの不足を埋めず、先に入力の意味と機構を整えた。

## 最小部品

`tools/demand_plans.py` の `promotion_features(records, series_id, issue_time, target_dates)` は、各対象日の予測発行時点までに公表された最新版を選ぶ。これは予測モデルではなく、将来特徴量候補と既知mask・選択版の出所を作る部品。既存 `demand_forecasting.py` の予測仕様・pinを変更していない。新しい部品をridgeや独自Transformerへ接続したものではない。

対象は日次×系列（店舗×商品群等）の**商品群全体の販促予定品目数snapshot**。販促一件だけの取消と、商品群全体で販促がなくなることは異なる。一件の取消から商品群合計0を作らない。最多4096入力snapshot/14対象日で、この制限を実行側上限やnative容量証明へ読み替えない。

| field | 意味 |
| --- | --- |
| series_id | 数量・品目群・販売範囲を固定した系列ID |
| target_date | 予定の対象civil date、YYYY-MM-DD |
| available_at | その版が予測へ利用可能になった日時、明示timezone offset付き |
| onpromotion | 予定の販促対象品目数。既知は非負整数、未知はnull |
| status | known / unknown / cancelled |
| source_kind | plannedのみ。実施値realizedを入力へ代用しない |
| scope | family_totalのみ。部分イベントから全体数量を作らない |
| source_id | 版を辿れる出所 |
| revision_id | 出所の版ID |

`available_at <= issue_time` の版だけを候補にし、対象日ごとに最も新しい公表版を選ぶ。時計はUTCへ正規化して比較し、対象日はcivil dateのまま残す。業務日へのtimezone対応はデータ側で決める。同じ対象日・公表時刻で複数版がある場合は、入力順で勝手に選ばず拒否する。

| 選択された状態 | count | known mask | 扱い |
| --- | ---: | --- | --- |
| known | 0以上 | true | 発行時点の既知予定。0も観測された予定値 |
| cancelled | 明示0 | true | 商品群全体の取消/販促なしが明示された版 |
| unknown | null | false | 未定と公表された最新版 |
| 利用可能な版なし | null | false | 記録なし。0と解釈しない |

後から未定になった版は古い確定版を上書きする。古い既知数量へ黙って戻さない。将来公表予定のrowは、数値payloadやstatusを使わない。予測起点で知らなかった取消・変更を遡って適用しない。

`source_kind`・`scope`・公表日時はcallerの宣言で、真の予定履歴と時計が確認された証拠ではない。原予定の版・保存記録と照合する必要がある。このparserの正常終了から実データのas-of正当性を補わない。

## 少数の機構確認

`tests/test_demand_plans.py` の新7件を一度だけ実行し、7passed/0failed。架空の系列・品目数・版で確認した内容は以下。

- 取消が公表される前は旧予定、ちょうど公表された時刻以降は取消版を選択する。異なるtimezone offsetでも同時刻を正しく比較する。
- 明示的な予定0と、記録がなく未知な日を別のmaskにする。
- 新しい未定版が古い確定版を上書きする。
- 将来公表payloadを使用不能な値に変えても現在の選択を変えない。
- 実施値と一件だけのイベントscopeを拒否する。
- 同時刻の競合版を入力順で選ばない。
- 負値・bool・非整数・timezoneなし・取消の非ゼロを拒否する。

架空ケースは入力機構の確認用で、売上予測・販促効果・PSIを評価していない。新fit/予測0、原ZIP読取り0、完成済み需要予測6確認・2016/2017評価・旧試験/CIの反復0。将来販促を既知にした架空データの精度を実設備・実需要の成績として報告しない。

## 次に進むためのデータ

実績評価を再開するため、最低限次の対応が必要。

1. 予測対象の販売/出荷実績、数量単位、営業日・欠品・改訂の意味。
2. 同じ系列に対応する販促計画の変更履歴。対象日、利用可能日時、予定/未定/取消、版・出所を残す。
3. 予測で支援する判断と必要な先読み期間。14日は公開小売pilotの暫定値で、製造/補充リードタイムの確定値ではない。

揃った場合、起点で既知の計画版だけを構築し、過去側で統計モデルの予定なし/ありを一つ比較する。実施後の販促実績を未来予定として与える評価は行わない。既に結果を確認した2017年窓を設定選択後の新しい未見testと呼ばない。新評価期間と選択境界を先に決める。

予定履歴が用意できなければ、販促予定の実績評価は止めたままにする。別の研究テーマへ進む場合は、最近の水準へ追随する統計機構、または取得済み設備データの限定研究等について、主問を新しく固定する。CARE to Compareは人の完了報告待ちで、自動取得・状態確認・再試行を行わない。
