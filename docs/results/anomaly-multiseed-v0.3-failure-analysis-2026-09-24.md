# v0.3 停止中・欠損重複時の見逃し調査（2026-09-24）

保存済みの開発・動作確認データを調べ、見逃しを3つの仕組みに分けた。停止中のコンベヤーは採点対象の速度がほぼゼロで、速度低下の異常が強い変化にならない。C2の停止中モーターは他信号による補正が電流の異常スコアを下げる。欠損と重なるセンサー異常は、計画時から連続2点の確認ができない設計だった。

今回確認した点では保存数値と計算式に不一致はなかった。ただし、保存済みprofileを起点にした局所検算であり、profileの学習や生成器まで含む独立検算の完了ではない。評価結果、候補、閾値、正解条件は変更していない。

## 調査範囲と根拠

- C1/C2、欠損なし、layout 0（モーター停止）と6（コンベヤー停止）を全10 seedsで確認：40評価。
- 最初の登録dev seed `2486912926863618161` のC1/C2、欠損あり、全12 layoutsを確認：24評価。
- 合計64評価の元JSONを完走保存点のSHA256と照合した。停止条件の機械異常440件、欠損ありのセンサー異常240件、合計680 incidentを調査。条件間で同じ基礎系列を使っており、680独立標本とは扱わない。
- 対象信号の6秒窓を調べ、利用可能な3,704 scoreについて保存profile・依存観測値から残差とscoreを計算式どおりに別途算出。絶対・相対許容誤差各`1e-12`以内で一致した。
- 最初のseedの停止2 layouts×2条件では、4つの元observationsファイルと1,680依存セル（値・quality）も照合した。他の依存値の元観測への照合、profileの再推定、全scoreの再計算は今回の範囲に含めない。

調査した元ファイルは68個・1,294,771,068 bytes、処理時間約40秒。1評価ずつ読み、新しい評価・データ生成・holdout参照は0。原本や過去の保存点を書き換えていない。

## 1. 停止中コンベヤー：速度の異常としては弱い

生成仕様では停止中の速度の基準値が0で、そこに小さなノイズを加える。機械異常は速度を55%下げ、0未満を切り上げる。同時に振動へ1.1を加える。停止中の速度をさらに下げても、通常運転時のような大きな速度差にはならない。

欠損なしの100 incidentずつで、C1/C2とも速度のscoreは6秒の評価窓全体で一度も閾値6を超えなかった。最大値はC1 **3.5862**、C2 **4.3225**。一方、振動由来の警報は全件に存在した。

| 欠損なし・layout 6 | 機械異常の検知 | 対象速度の閾値超過 | 最初の設備警報の信号 |
| --- | ---: | ---: | --- |
| C1 | 0/100 | 0件 | 振動100件 |
| C2 | 0/100 | 0件 | 振動のみ91件、温度と振動9件 |

登録ルールは「何らかの設備警報」ではなく、正解異常と同じ対象信号が最初の設備警報と同時に立ち上がることを要求する。この異常の対象は速度なので、振動警報だけでは正解にならず、全件`first_candidate_no_target_onset`となった。後続の適格な速度警報を取り落とした事例でもなく、窓内に速度の警報開始自体がなかった。

これは今回の合成異常の作り方・検知方式・採点対象の組合せによる限界と整理できる。計画§3.2にも停止・減速中の物理的妥当性を保証しない旨がある。実設備で故障に気づけないと断定せず、振動を正解に付け替えたり停止条件を分母から除いたりしない。

## 2. 停止中モーター：C2の補正が電流の異常を弱める

欠損なしの100 incidentでC1は100件検知し、C2は79件検知・21件見逃しだった。C2の見逃しは3つのdev seedsに6件・10件・5件あり、残る7 seedsは0件だった。

この配置では異常が運転段階の開始と重なるため、offset 0秒は全方式で判定対象外。3秒間の異常中に残るoffset 1秒と2秒の両方が閾値を超える必要がある。C2の21件は、1秒だけ不足9件、2秒だけ不足5件、両方不足7件で、計28点が閾値以下だった。全21件で振動の警報はあったが、電流の警報開始は評価窓内になかった。

同じ21 incidentのC1の1・2秒点はすべて閾値を超え、scoreは6.9343～8.6413。C2で不足した28点は5.2003～5.9652だった。C2の残差を信号ごとの項に分けると、28点すべてで他信号の合計項が電流自身の負方向の項を打ち消す向きに働き、最大の寄与は振動だった。

例：最初のdev seed、cycle 1、異常開始1秒後。

| 値 | 保存値・計算値 |
| --- | ---: |
| 電流自身の項 | -7.684583 |
| 他3信号の合計項 | +1.910567 |
| うち振動の項 | +1.887808 |
| C2残差（全項合算） | -5.774016 |
| calibration center / scale | -0.197109 / 1.060875 |
| C2 score | 5.256895（閾値6以下） |
| 同時刻のC1 score | 7.027234（閾値6超過） |

項の分解による補助確認では、28点とも電流自身の項だけを同じcenter/scaleで評価すれば6を超える。ただし、それは正式な別候補の性能評価ではなく、打ち消しの方向を説明する数式上の確認である。補正を除いた候補を再学習・再較正した結果とは扱わない。

計画§4.2は、複数信号に同時に異常が及ぶと相関モデルが異常を相殺する可能性を明示している。今回の観測はそのリスクと整合する。閾値の引下げや振動を除いたC2への変更は今回行わない。

## 3. センサー異常と欠損：90%は登録済みの構造的上限

計画§3.3では、各layoutの10回目のセンサー異常に欠損を重ねる。異常は開始から3秒、欠損は開始1秒後から3秒。現在値に加えて直前値のqualityも必要なので、判定の可否は次のようになる。

| 異常開始からの秒数 | 温度の状態 | 判定への影響 |
| --- | --- | --- |
| 0秒 | 異常値あり | 判定できても1点だけ。運転段階の切替と同時なら判定対象外 |
| 1～3秒 | 欠損 | 現在値がなく判定できない |
| 4秒 | 値は戻るが直前は欠損 | 共通の履歴quality条件で判定できない |
| 5秒 | 値・履歴とも復旧 | 異常終了後。0秒から連続しない |

この6秒窓では利用可能な2点が隣り合わず、連続2点の根拠は構造上作れない。今回の最初のseedの全12 layouts×C1/C2で、最初の9回は検知、10回目は`no_candidate_in_window`で見逃しとなることを確認した。これは、先の720評価の全件集計における各方式の欠損あり1,080/1,200＝90%と整合する。

したがって「90%になった理由が未解明」という扱いは解消する。欠損を含めた検知限界を測るための意図された条件であり、この10%を不具合として直ちに修正したり、分母から外したりする必要はない。全seedのセンサーincident欄を今回再読したわけではない点は区別する。

## 結論と次の作業

1. 今回の局所調査では計算式との不一致は確認されず、見逃しは上記の仕様・方式・信号特性で説明できた。結果の除外、閾値調整、追加の長時間試験は不要。
2. 次は**保存観測からprofile・scoreを導く独立consumer**の不足分を進める。具体的には、観測の時刻・qualityからphase/availabilityを求め、正常fit/calibrationからC0/C1/C2のprofileを別実装で復元し、そのprofileから残差とscoreを照合する。今回の局所照合は、その回帰確認用の保存例として使える。
3. 別途、正常生成・overlay・丸め、bootstrap/CI/gateの独立実装、単一writer運用の受入・runtime inventory・実行資源の確定が残る。正式holdoutの生成・評価はこれらの前提を整えてから行う。
