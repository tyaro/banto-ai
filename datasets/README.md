# Dataset policy and layout

## Allowed in Git

- Synthetic data generated by the repository tools.
- Public datasets whose license permits redistribution, with source and license recorded.
- Tiny fixtures required for tests, containing no customer information.
- Manifests that identify data without embedding sensitive observations.

## Never commit

- Customer or plant data.
- Raw exports from Banto Hub or a PLC.
- Credentials, connection strings, equipment-identifying metadata, or unredacted logs.
- Generated checkpoints or large experiment outputs.

The repository `.gitignore` blocks common data and artifact extensions as a backstop, not as a substitute for review.

## Local-only layout

```text
datasets/
  README.md
  manifests/       versioned metadata-only manifests
  fixtures/         tiny safe test fixtures
  local/            ignored local/public data
```

For customer work, keep data in the approved external storage boundary and reference it with a pseudonymous `dataset_id`. A run manifest should record provenance, units, sampling, quality flags, transformations, and split boundaries.
